# TEST ШЭП: первый реальный SOAP POST (не ФНО)

## Что делает

В Android TEST открой «ИСНА · тестирование»:

1. «Получить SOAP с TEST-сервера и подписать локально».
2. Выбери .p12 и подпиши. KalkanCrypt проверит SOAP Body после сериализации.
3. «Проверить подписанный SOAP на TEST VPS».
4. «Отправить пробный SOAP в TEST ШЭП». Подтверди отдельным диалогом.

На этом шаге TEST VPS **действительно отправит один HTTP SOAP POST** через
существующий IPsec туннель: исходящий `195.49.215.49`, назначение
`195.12.113.7:80/bip-sync-wss-gost/`. В ответе покажет статус HTTP,
наличие SOAP Fault и краткое сообщение шлюза.

## Границы безопасности

- Только `APP_MODE=test`, вход в аккаунт + выбранная организация + подтверждение.
- Только **синтетический** подписанный SOAP, в котором
  `serviceId=NIKA_ISNA_OFFLINE_SIGNING_ONLY`, `senderId=nika-offline-test`.
- Никаких реальных ФНО, ИИН, БИН, сумм, ключей или паролей.
- SOAP **не пересериализуется** после подписи — на wire идут исходные UTF-8 bytes.
- Вызов не использует произвольные URL/порты и не подставляет настоящий senderId.
- Включён аварийный переключатель `ISNA_BIP_TEST_POST_ENABLED=0` для запрета.
- Сервер проверяет только структуру XMLDSig. Подлинность подписи локально
  проверяет Android; тестовый ШЭП может её проверить независимо.
- Даже HTTP 200 или SOAP Fault не означают успешную авторизацию/регистрацию
  подписи и тем более не означают сдачу ФНО.

## Ожидаемые ответы

- `SOAP Fault: unknown service` — достаточно для проверки доставки до шлюза.
- `HTTP 401/403` — аутентификация/права; может означать, что шлюз отверг
  транспортную подпись. Нужен текст ответа ВШЭП.
- `Нет ответа через IPsec` — соединение не установлено/тайм-аут; убедись,
  что приложение и сервер работают в TEST и на VPS есть адрес источника.

## Тесты

```bash
cd /var/www/nika-business-test
sudo -u www-data .venv/bin/python -m unittest discover \
    -s tests -p 'test_isna_shep_transport_test.py' -v
```

Все тестовые обращения к HTTP замоканы; CI не обращается в государственный шлюз.

Следующий этап после получения ответа: отдельный **разрешённый** процесс
настоящего `FNO_INTEGRATION` с корректной схемой формы, контролем статуса
ФНО и проверкой прав подписанта. Боевой код подачи НЕ включён.
