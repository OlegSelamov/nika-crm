# ИСНА TEST: проверка настоящего FNO_INTEGRATION без отправки ФНО

Это настоящий сетевой POST к тестовому ШЭП, однако не отправка налоговой
декларации. Никакие ИИН, БИН, суммы налогов и подписанная бизнес-ФНО
не используются.

## Отличия от предыдущего теста

- serviceId: FNO_INTEGRATION (официальный ключ КГД).
- senderId: конфигурация ISNA_BIP_SENDER_ID из TEST VPS (без пароля).
- requestData/data: xs:string со строго фиксированным текстом <root/>,
  без JSON, формы и внутренней подписи налогоплательщика.
- SOAP Body: единственная транспортная XMLDSig GOST 2015-512, KeyIdentifier.
- Цель: отличить ошибки сервиса/доступа/формата, НЕ получить квитанцию ФНО.

## Проверка в Android TEST

1. В разделе «ИСНА · тестирование» выбери «Проверить маршрут FNO_INTEGRATION · без ФНО».
2. Выбери .p12, подпиши через KalkanCrypt. Ключ остаётся на Android.
3. Nika TEST VPS проверит структуру и независимо проверит GOST-подпись SOAP Body,
   если на сервере настроен совместимый xmlsec1. Никаких POST в ШЭП пока.
4. При успешной независимой проверке подписи нажми «Отправить маршрутный тест в TEST ШЭП»
   и отдельно подтверди отправку. Без криптопроверки эта отправка заблокирована.
5. Сохрани код ошибки и sessionId ШЭП для диагностики прав на сервис.

## Ограничения

- Только APP_MODE=test, авторизованная сессия и выбранная организация,
  настроенный ISNA_BIP_SENDER_ID и фиксированный TEST URL.
- Дополнительный стоп-переключатель на TEST VPS:
  ISNA_BIP_ROUTING_PROBE_ENABLED=0 (по умолчанию тест разрешён после
  отдельного подтверждения пользователем).
- Поддерживаются только точный <root/>, один SOAP Body,
  сервис FNO_INTEGRATION, строгая проверка senderId на сервере,
  messageDate в интервале 15 минут и один WSSE KeyIdentifier.
- Подпись локально проверяется на Android после сериализации. На VPS
  её независимо проверяет GOST-совместимый xmlsec1 (если установлен).
  Без такой проверки TEST VPS возвращает `unavailable` / `unsupported`,
  а маршрутный POST блокируется. Сертификат извлекается из самого SOAP.
- Чтобы сверять ожидаемый публичный сертификат **без загрузки .cer на VPS**,
  можно задать `ISNA_BIP_REGISTERED_CERT_SHA256=<SHA-256 DER публичного сертификата>`
  в TEST. При несовпадении тестовый POST блокируется.
- SOAP пересылается на TEST ШЭП как подписан, без пересериализации.
- Сервер не логирует и не сохраняет сырые XML, не раскрывает senderId
  в диагностическом ответе. SOAP Fault на пустой бизнес-ФНО ожидаем.
- Тест НЕ доказывает, что сертификат зарегистрирован в Smart Bridge или
  доступ разрешён. Реальная ФНО будет отдельной интеграцией с корректной
  схемой и внутренней подписью.
- PROD не затронут.
