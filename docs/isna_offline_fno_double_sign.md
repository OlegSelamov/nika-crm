# ИСНА: локальная проверка двух подписей на Android

Этот этап использует форму SOAP из примера сервиса `FNO_INTEGRATION`, но **не является отправкой декларации**.

## Как проверить

1. Открыть **ИСНА · тестирование** на Android TEST.
2. Нажать **Проверить две подписи ФНО · локально**.
3. Выбрать .p12 пользователя для подписи внутреннего XML. Ключ и пароль используются только на телефоне.
4. Выбрать .p12 транспортной подписи для подписания SOAP Body; возможно использовать другой сертификат.
5. Проверить статус обеих подписей и при необходимости сохранить XML для локальной проверки.

## Безопасность

- `serviceId=FNO_INTEGRATION` соответствует примеру паспорта Smart Bridge, но `senderId=nika-fno-offline-only` и код формы `000.00` намеренно не подходят для подачи.
- `fnoDto` содержит только `{"nikaOfflineDemo":true}`, нет ИИН, БИН, сумм или личных данных.
- Проба формируется и подписывается **исключительно локально**. Ни на Nika TEST VPS, ни в ВШЭП и ИСНА SOAP не отправляется.
- Native Kotlin перед подписанием транспорта проверяет строго заданный набор полей и криптографически проверяет внутреннюю XMLDSig с открытым сертификатом, включённым в неё. Затем существующий KalkanCrypt подписывает SOAP Body по `wsu:Id` и проверяет результат после сериализации.
- Проверка локальной подписи **не подтверждает**, что сертификат зарегистрирован в Smart Bridge, прошёл OCSP/CRL, подходит по правам подписи или будет принят ШЭП.
- Существующие диагностические запросы на TEST VPS, боевой интерфейс и отправка ФНО не изменяются.

## Важно для следующего этапа

Нужны независимая криптографическая проверка подписанного SOAP/ФНО принимающей системой, подтверждение требований ВШЭП к идентификаторам и полномочиям, а также реальная схема ФНО 910/200. Полученная XSD `declareRequestResponseTypes.xsd` содержит только строковые элементы и не валидирует внутренний JSON ФНО.

Только после этих проверок можно отдельно реализовать и включить TEST POST в ШЭП. Продакшен остаётся выключенным.
