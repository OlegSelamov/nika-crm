# ИСНА TEST: экспериментальный WS-Security X509v3 KeyIdentifier

## Причина

Ранее тестовый ШЭП вернул HTTP 500 SOAP Fault «Транспортная подпись не актуальная» (вероятно, код SCE005). Локальная проверка SOAP через Android/KalkanCrypt успешна; сертификат совпадает с выбранным публичным .cer, но **регистрация в Smart Bridge не подтверждена**.

По ответу НУЦ РК на форуме (2025-03-27), прямого метода SignWSSE() в Java SDK нет: он относится к KalkanCryptCOM.dll. Android использует Java KalkanCrypt+Apache XML Security, поэтому **мы не вызываем SignWSSE()** и не утверждаем, что результат идентичен COM. Вместо этого добавлен второй, отдельно выбираемый тестовый WS-Security профиль, соответствующий структуре X509v3 KeyIdentifier из доступных примеров SignWSSE.

## Как проверить на Android TEST

1. «Получить SOAP и подписать WSSE KeyIdentifier · TEST».
2. Выбрать тот же .p12, который использовался в предыдущем тесте. Закрытый ключ и пароль остаются на телефоне.
3. Приложение подписывает SOAP Body по неизменённому wsu:Id, GOST 2015-512 и exclusive C14N. Вместо ds:X509Data в ds:KeyInfo размещается wsse:SecurityTokenReference/wsse:KeyIdentifier, с ValueType X509v3 и сертификатом в Base64.
4. Подпись проверяется **локально после сериализации**.
5. «Проверить подписанный SOAP на TEST VPS» — сервер принимает только существующий синтетический безопасный SOAP и проверяет профиль и структуру, но криптографически подпись не проверяет.
6. При необходимости отдельно сравнить публичный .cer на телефоне; затем «Отправить пробный SOAP в TEST ШЭП» с явным подтверждением. Это реальный POST, но **не настоящая ФНО**.

Сервер возвращает certificateProfile: key-identifier либо x509-data. Для сравнения сохранили прежний профиль ds:X509Data и кнопку без изменений. Подписанный SOAP перед отправкой **не пересериализуется**.

## Ограничения

- Изменение только в TEST; prod/реальная подача ФНО не затронуты.
- Для тестового POST используются несуществующий serviceId NIKA_ISNA_OFFLINE_SIGNING_ONLY, вымышленный senderId и отсутствие налоговых данных.
- Ни KalkanCrypt на Android, ни структурная проверка VPS не подтверждают, что сертификат зарегистрирован в Smart Bridge, имеет нужные полномочия, не отозван или что ШЭП его примет.
- Код SCE005 не доказывает конкретную проблему XML-структуры; может потребоваться запросить у оператора проверку зарегистрированной транспортной подписи.
- Ранее использованный .p12 действует до 04.11.2026. После этой даты он не подходит для новых подписей, и сертификат следует переоформить и актуализировать в Smart Bridge.
